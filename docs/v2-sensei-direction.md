# Execution Sensei v2 direction

## Product shift
V1 was framed mainly as an execution-enforcement tool.
V2 reframes the app as a sensei-like cognitive discipline system.

The app's primary job is no longer just blocking distraction.
Its job is to restructure thought under pressure:
- catch avoidance
- compress overthinking into one action
- interrupt self-negotiation
- restore disciplined attention
- help the user re-enter aligned action quickly

## Core thesis
Execution Sensei is a brutally honest digital sensei that detects drift, confronts weak thinking, and trains immediate recommitment to the next right move.

## Design principles
- more dojo, less diary
- guidance should be sharp, brief, and specific
- discipline before mood
- action before analysis loops
- recovery from drift matters as much as prevention
- the app should never pretend to be a therapist

## Mental patterns the app should target
- avoidance
- rationalized delay
- fake progress
- scattered attention
- emotional reasoning
- compulsive stimulation seeking
- endless tweaking instead of execution

## V2 product pillars
1. Focus framing
   - define the current target
   - define the next physical action
   - define the done condition

2. Drift interception
   - identify when the user is wandering or escaping discomfort
   - interrupt with corrective language

3. Thought correction
   - call out distortions directly
   - replace vague emotion-led thinking with concrete action-led framing

4. Disciplined recommitment
   - require the user to choose and restate the next move
   - reduce the chance of vague re-entry

5. Pattern review
   - show where the user repeatedly collapses
   - identify triggers, lies, and weak conditions

## UX tone
Not hype.
Not comfort-first.
Not cheerful accountability fluff.

Preferred tone:
- calm
- precise
- demanding
- unsentimental
- corrective

Examples:
- "You are splitting attention. Reduce scope."
- "This is escape, not strategy."
- "Name the next physical action."
- "Return to target."
- "No self-negotiation."

## Reality constraints
Android can provide friction, interruption, and redirection.
It cannot provide perfect hard lockout under the current allowed constraints.
V2 should stay honest about that and differentiate on disciplined guidance, not false promises.
